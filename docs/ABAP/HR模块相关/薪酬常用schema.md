# 薪酬常用 schema：按功能理解 PE01 与 PE02

> 整理日期：2026-10-12。通用概念参考 SAP 官方文档；项目例子已只读核对 BAESL_100 当前的 schema、PCR 和标准实现。教学片段用于理解，不是完整的上线规则。
>
> 配套笔记：[考勤常用 schema](考勤常用schema.md)。

## 1. 先分清：schema、函数、PCR、操作

| 层次 | 维护入口 | 负责什么 | 例子 |
| --- | --- | --- | --- |
| Schema（计算方案） | PE01 | 安排计算顺序、条件分支、子方案调用 | ZA01 |
| Function（函数） | PE01 中的一行；PE04 查定义 | 读取数据、处理内部表、调用 PCR、控制流程 | WPBP、PIT、PITAB、IF |
| PCR（人员计算规则） | PE02 | 对传入的数据执行具体判断、计算和输出 | ZBOT、ZPP2、ZAA0 |
| Operation（操作） | PE02 中的一条指令；PE04 查定义 | 取值、比较、修改当前记录、写入输出表 | CMPER、OUTWP、RTE、ZERO=、ADDWT |

**PE01 决定“什么时候、拿什么数据、调用哪条规则”；PE02 决定“这条数据怎么算、往哪里输出”。**

这里的“函数”是薪资引擎中的函数，不代表同名的 SE37 函数模块。某些名称在函数和操作中都存在，例如 PRINT，必须结合所在位置阅读。

COPY 后面是子 schema 名，不是 PCR 名；PCR 则通常由 PIT、ACTIO 等函数调用。参见 [SAP：Schema 的组织方式](https://help.sap.com/docs/ERP_HCM_SPV/d3bc4479e3344626be836c03a5c6962f/d9cae05320a7424de10000000a174cb4.html?locale=en-US&state=PRODUCTION&version=EHP8_HRSP_F1)。

## 2. 按目的快速查找

| 想做什么 | PE01 常用函数 | PE02 常用操作 | 首先确认 |
| --- | --- | --- | --- |
| 读取人员和基本工资数据 | WPBP | OUTWP 查询属性 | 生效期间、WPBP 分段 |
| 读取经常性支付、补充支付 | P0014、P0015 | 调用的 PCR 内再处理 | IT0014、IT0015 及函数参数 |
| 逐条处理工资项 | PIT、PRT | RTE、NUM、AMT、ADDWT | 输入是 IT 还是 RT |
| 比较数值或期间 | IF 组织流程 | AMT?、NUM?、RTE?、CMPER | 比较对象、期间、返回分支 |
| 判断工资范围、员工组等 | IF 调用判断 PCR | OUTWP | 实际查询的字段 |
| 按工资项属性分流 | PIT 调用 PCR | VWTCL | 处理类号及其配置值 |
| 加减乘除 | 调用相应 PCR | RTE、NUM、AMT、MULTI、DIVID | 结果写回 R、N、A 中哪一个 |
| 输出当前工资项 | PIT 等提供处理上下文 | ADDWT | 目标表、工资项号、split |
| 保存或恢复整张工作表 | PITAB | 不等于 ADDWT | 操作码和指定表 |
| 清零当前数值 | 调用相应 PCR | ZERO= | 当前字段，不是历史结果 |
| 清空或重置工作表 | PITAB D | 不等于 ZERO= | 有些表会重新初始化 |
| 调子方案、调子规则、续行 | COPY、ACTIO、PIT | PCY、GCY、NEXTR | 调用层次、是否返回 |
| 控制日志 | PRINT、BLOCK | PRINT | 所在处理步骤 |

## 3. 计算过程中流转的数据

### 3.1 常见内部表

| 表 | 用途 | 阅读时注意 |
| --- | --- | --- |
| IT | 当前步骤的工资项输入表 | 不是数据库中的信息类型表 |
| OT | PCR 处理时形成的输出表；也有当前记录工作区 | ADDWT 通常向此输出 |
| RT | 本次工资结果表 | 包含金额工资项和技术工资项，不全是最终实发 |
| CRT | 累计工资结果 | 累计口径由配置和规则决定 |
| WPBP | 工作中心、基本支付及期间分段 | 一人一个月可以有多段 |
| VAR | 规则使用的变量存储 | 不是持久化主数据表 |
| PSP | 个人工作计划 | 与计划工作日、工作时间有关 |
| DPS | 工作计划处理使用的辅助表 | PITAB D DPS 会特殊初始化 |
| ZL | 时间工资项 | 可从时间评估导入，再参与薪资计算 |

典型 PIT 数据流：

~~~mermaid
flowchart LR
  A["IT：输入工资项"] --> B["PIT：逐条调用 PCR"]
  B --> C["修改当前记录的 R / N / A"]
  C --> D["ADDWT：写入 OT"]
  D --> E["供后续步骤继续处理"]
  E --> F["估值、累计等处理"]
  F --> G["RT 等工资结果"]
~~~

这是常见 PIT 处理方式。ACTIO、PRT、带修饰符的 ADDWT 等上下文可能不同，不能把所有规则套成同一张表的处理。

### 3.2 R、N、A 是三个字段，不是三种工资项

| 简写 | 操作 | 字段 | 常见含义 |
| --- | --- | --- | --- |
| R | RTE | BETPE | 单价、费率，也可能是技术计算因子 |
| N | NUM | ANZHL | 数量，如天数、小时数、次数 |
| A | AMT | BETRG | 金额 |

例如当前工资项的 R = 100，N = 2：

~~~text
MULTI RNA
ADDWT *
~~~

MULTI RNA 表示 R × N → A，得到 A = 200；ADDWT * 再把当前记录输出。

**改了 AMT/RTE/NUM，不代表已经写入输出表；有工资项数量，也不代表已经算出金额。**

## 4. PE02 操作：按功能分类

### 4.1 取值、赋值和恢复

| 操作或例子 | 含义 | 易错点 |
| --- | --- | --- |
| RTE=… | 给当前 R 赋值 | 右侧可能是常数、技术参数或其他来源 |
| NUM=… | 给当前 N 赋值 | 单位由工资项和规则决定 |
| AMT=… | 给当前 A 赋值 | 赋值覆盖当前字段，不是累计 |
| RTE=KGENAU | 从常数 GENAU 取得值放入 R | K 是来源标识；GENAU 常用于因子精度处理 |
| RTE=TSSOLL | 从对应的部分期间技术参数取值 | 结合 PARTT、当前分段核对来源和单位 |
| FILLF RNA | 从当前输入工资项恢复 R、N、A | 不是清零，也不是读取任意工资项 |
| OUTWP… | 查询人员/工作中心属性，形成判断键 | 通常用来分支，不是把值放入 AMT |

不同来源有不同参数语法。不要把 KGENAU、TSSOLL、工资项号都当成普通数字；PE02 中的空格和固定参数位置也有意义。

### 4.2 比较和判断

| 操作 | 判断什么 | 典型结果 |
| --- | --- | --- |
| AMT?… | 当前金额与指定值比较 | <、=、> |
| NUM?… | 当前数量与指定值比较 | <、=、> |
| RTE?… | 当前费率/因子与指定值比较 | <、=、> |
| CMPER 2606 | 当前所属期间与 2026 年第 06 期间比较 | <、=、> |
| OUTWPPAYSB | 查询工资范围 ABKRS | 例如 BB |
| OUTWPPERSG | 查询员工组 PERSG | 员工组值 |
| OUTWPPERSB | 查询员工子组 PERSK | 员工子组值 |
| OUTWPCOMPY | 查询公司代码 BUKRS | 公司代码 |
| OUTWPPLANT | 查询人事范围 WERKS | 人事范围 |
| VWTCL 10 | 查询当前工资项的处理类 10 | 配置值，不是工资项金额 |
| PPPAR A | 查询期内离职/有效计算期结束边界等部分期间状态 | 成立为 A，否则通常为 * |
| PPPAR E | 查询期内入职/有效计算期开始边界等状态 | 成立为 E，否则通常为 * |
| PPPAR S | 查询是否有 WPBP 分段状态 | 成立为 S，否则通常为 * |

PPPAR 的 A、E 还涉及计算期边界标志，不应只凭人事事件名称判断分支。

**判断操作选择 PE02 树上的路径，不自动完成输出。** 进入分支后，仍要看后面的赋值、计算和 ADDWT。

### 4.3 加减乘除与舍入

| 操作或例子 | 含义 |
| --- | --- |
| AMT+… / AMT-… | 当前 A 加上/减去右侧值 |
| NUM+… / NUM-… | 当前 N 加上/减去右侧值 |
| RTE*… / RTE/… | 当前 R 乘以/除以右侧值 |
| RTE*8 | 当前 R 乘以 8 |
| RTE/TSDIVP | 当前 R 除以 TSDIVP 对应的技术参数 |
| MULTI RNA | R × N → A |
| DIVID ANA | A ÷ N → A |
| ROUND | 按指定字段、方向和精度舍入；参数查 PE04 |

MULTI、DIVID 的三个字母依次表示“第一个数、第二个数、结果字段”。DIVID ANA 是 A ÷ N 后放回 A。

除法要核对分母。日薪除数、计划工时、自然日数不是同一口径；固定 8 也不能自动推广为所有人员每天工作 8 小时。

### 4.4 输出、复制和累计

| 操作 | 常见作用 | 注意 |
| --- | --- | --- |
| ADDWT * | 按当前工资项号向 OT 输出当前记录 | 输出当前计算后的值 |
| ADDWT 1000 | 以工资项 1000 向 OT 输出当前记录 | 原工资项不会因此自动再输出一次 |
| ADDWTE* | 按当前工资项号向 RT 输出 | E 改变目标表 |
| ADDWTE/101 | 以 /101 向 RT 输出 | /101 的业务含义还依赖配置 |
| ADDWTI* | 向 IT 输出 | I 改变目标表；需核对调用上下文 |
| FILLF RNA | 恢复当前输入记录的数值 | 不会单独输出记录 |

ADDWT 可按目标键收集记录，不是“每次一定新增独立一行”。工资项号、split 等会影响是否合并。不同目标表形式可查 [SAP：Payroll Schema and Personnel Calculation Rules](https://help.sap.com/docs/SUPPORT_CONTENT/erphcm/3354685492.html)。

~~~text
ADDWT *
ADDWT 1000
~~~

这个片段输出原工资项，再以 1000 输出一份。若当前工资项已经是 1000，或后续又累计同样的数据，可能造成重复金额。

### 4.5 清零、split 和分组

| 操作 | 作用 | 不代表什么 |
| --- | --- | --- |
| ZERO= A | 当前 A 清零 | 删除 RT 的所有金额 |
| ZERO= N | 当前 N 清零 | 删除人员考勤记录 |
| ZERO= R | 当前 R 清零 | 更改费率主数据 |
| ZERO= RNA | 当前 R、N、A 全清零 | 清空整个 IT/RT |
| ELIMI A | 消除当前记录的 WPBP split 标识 | 删除 WPBP 表 |
| RESET A | 恢复对应的 split 标识 | 把数值恢复成零 |
| MODIF | 设置后续处理使用的分组/修饰符 | 直接修改人员主数据 |

split 不是无关字段。随意 ELIMI 可能合并原本应分段处理的数据，应先确认业务允许合并。

### 4.6 调用、跳转、续行与条件返回

| 操作 | 作用 | 区别 |
| --- | --- | --- |
| PCY | 调用另一条 PCR，完成后返回 | 类似子程序调用 |
| GCY | 转到另一条 PCR 继续处理 | 与 PCY 的返回行为不同 |
| NEXTR A | 继续同一规则路径中序号为 A 的后续行 | A 是续行序号，不是新判断结果 |
| SCOND=T IF | 给调用方 IF 返回“真” | 不是工资项输出 |
| SCOND=F IF | 给调用方 IF 返回“假” | 不是清空金额 |
| PRINT | 输出相应处理位置的日志信息 | 不等于保存工资结果 |

`*` 不能统一翻译为“全部”。它可以表示通用匹配，也可以在 ADDWT * 中表示“当前工资项”。`**` 与 `****` 的长度可能对应不同判断键或工资项键，不能随意缩成一个星号。

## 5. CMPER：回算时比较哪个期间

### 5.1 CMPER 2606 的含义

本次核对的标准实现中，**无 R 修饰符的 CMPER 2606 比较 APER-PAPER，即当前正在计算的所属期间（for-period）与 202606**。

它不是拿系统日期 SY-DATUM 比较，也不是直接拿“在哪个月运行核算”（in-period）比较。

| 执行场景 | 所属期 | 所在期 | 与 2606 比较 |
| --- | --- | --- | --- |
| 2026 年 10 月正常核算 | 202610 | 202610 | > |
| 2026 年 10 月回算 5 月 | 202605 | 202610 | < |
| 2026 年 10 月回算 6 月 | 202606 | 202610 | = |
| 2026 年 10 月回算 9 月 | 202609 | 202610 | > |

这里按月度工资期间解释；非月度工资范围中的“第 06 期间”未必等于自然月 6 月。CMPER 带 R 等修饰符时有其他语义，需另查 PE04。

### 5.2 BAESL_100 的 ZBOT 例子

2026-10-12 读取到：ZBOT 对工资项 5000、5010、5020 使用相同分支；其他工资项通过通用入口输出。下面用 5000 展示：

~~~text
工资项 5000
  OUTWPPAYSB
    **  → ADDWT *
    BB  → CMPER 2606
            <  → ADDWT *
            *  → ZERO= RNA
~~~

1. OUTWPPAYSB 得到工资范围；BB 是 ABKRS 的值。
2. 其他工资范围走 **，输出当前工资项。
3. BB 再比较所属期间。
4. 早于 202606，执行 ADDWT *。
5. 等于或晚于 202606，走剩余分支 *，清零且没有 ADDWT。

在该 PIT 上下文中，最后一个分支不把当前工资项传入 OT。作用范围是当前这次处理；后续步骤仍可能另外生成工资项。

**“6 月起生效”按所属期判断：10 月回算 5 月走旧分支；10 月回算 6 月走新分支。** 不等于所有回算月份都保持旧规则。

## 6. OUTWPPAYSB：工资范围与员工子组不能混淆

拆开读就是“OUTWP 操作 + PAYSB 查询参数”。

| 写法 | 本次核对的取值来源 | 含义 |
| --- | --- | --- |
| OUTWPPAYSB | APER-ABKRS | 当前核算上下文中的工资范围 |
| OUTWPPERSG | 对应 WPBP 段的 PERSG | 员工组 |
| OUTWPPERSB | 对应 WPBP 段的 PERSK | 员工子组 |

PAYSB 和 PERSB 很像，但不是同一字段。项目口头称“BB 序列”，也不能据此推断为员工子组，应看规则实际取值。

OUTWP 把查询值交给后续分支，不把 BB 转成金额，也不直接改工资项。

## 7. ZERO= 与 ADDWT：清零和不输出的区别

以普通 PIT 调用为前提：

| 分支末尾 | 当前工作区 | 是否显式输出到 OT |
| --- | --- | --- |
| ADDWT * | 不要求清零 | 是 |
| ZERO= A → ADDWT * | 金额清零，数量、费率可保留 | 是 |
| ZERO= RNA → ADDWT * | 三个数值字段清零 | 是；零值记录是否保留还受后续处理影响 |
| ZERO= RNA，之后没有 ADDWT | 三个数值字段清零 | 否 |
| 没有任何 ADDWT 的结束分支 | 取决于之前的操作 | 否 |

ZERO= 不能撤销前面已经 ADDWT 出去的记录。“先 ADDWT，再 ZERO=，然后结束”不会自动删除第一次输出。

所以不能只检查有没有 ZERO=，还要检查 ADDWT 的位置、目标表和执行次数。

## 8. PE01 函数：按功能分类

### 8.1 读取与准备数据

| 函数 | 主要作用 |
| --- | --- |
| WPBP | 建立工作中心、基本支付等数据及 WPBP 分段 |
| P0014 | 处理 IT0014 经常性支付/扣款 |
| P0015 | 处理 IT0015 补充支付 |
| P2010 | 处理 IT2010 员工报酬信息 |
| GENPS | 生成个人工作计划 |
| PARTT | 准备部分期间计算使用的时间、分段等参数 |
| P2003 | 处理替代记录；具体工作表由参数决定 |
| RAB | 为缺勤处理准备内部缺勤数据 |
| PAB | 按缺勤估值逻辑处理缺勤 |

看到 PAB，不能直接认定“这里已经算出最终病假扣款”。缺勤处理可能先生成数量或工资项，之后才估值。参见 [SAP：Absence Valuation](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/8e44bafcbdcb4d6b85e4564d69a14500/ae17dd5321e8424de10000000a174cb4.html?locale=en-US&state=PRODUCTION&version=2025.001)。

### 8.2 表处理与规则调用

| 函数 | 主要作用 | 便于理解的读法 |
| --- | --- | --- |
| PIT | 对 IT 中的工资项调用 PCR | 拿 IT 逐条算 |
| PRT | 对 RT 中的工资项调用 PCR | 拿 RT 逐条处理 |
| ACTIO | 调用 PCR 执行一组操作 | 不等于逐条遍历 IT |
| PITAB | 保存、装载、重置等内部表操作 | 处理一张工作表 |
| ZLIT | 将时间工资项送入 IT | 后面继续薪资处理 |

### 8.3 流程控制和时间结果衔接

| 函数 | 主要作用 |
| --- | --- |
| COPY | 包含子 schema |
| IF / ELSE / ENDIF | 有条件地执行 schema 段 |
| LPBEG / LPEND | 控制特定循环，范围由函数参数定义 |
| BLOCK | 组织处理块和日志层次 |
| PRINT | 输出指定计算信息供日志查看 |
| IMPRT | 按参数导入结果，例如 B2 时间评估结果 |
| DAYPR | 在薪资处理中按日执行时间处理子方案 |

独立时间评估产生时间工资项，再由薪资导入处理，是常见路径；也存在工资核算内的按日时间处理。实际走哪条路径，要看 schema 和条件。参见 [SAP：时间工资项的形成与薪资衔接](https://help.sap.com/doc/85fc7972fb944a6aac27b727cc3ac134/EHP7_HRSP_I1/en-US/e138c2531bb9b44ce10000000a174cb4.html?forSiteMap=true)。

## 9. PIT 的 GEN、NOAB 与参数列

PE01 常见列为“函数、参数 1、参数 2、参数 3、参数 4”。下表 `—` 表示空白，不是实际输入字符。

BAESL_100 的 ZA01 当前例子：

| 行号 | 函数 | 参数 1 | 参数 2 | 参数 3 | 参数 4 |
| --- | --- | --- | --- | --- | --- |
| 016 | PIT | ZAA0 | GEN | NOAB | — |
| 044 | ZLIT | — | — | — | AMS |
| 045 | PIT | ZBOT | — | NOAB | — |
| 063 | P0014 | CN11 | GEN | NOAB | — |
| 064 | P0015 | CN11 | GEN | NOAB | — |

对 PIT 而言：

- 参数 1 是调用的 PCR。
- GEN 使用规则的通用工资项入口 ****，而不是按输入工资项号选择具体入口。
- NOAB 使用通用的人员计算规则分组入口 *。这里是“用于 PCR 的员工子组分组”，不能直接等同于 PERSK 员工子组编码。
- 空白参数仍占位置，不能把后面的值整体左移。

ZBOT 依赖 5000、5010、5020 的独立入口，当前调用没有 GEN。若改为 GEN，可能只进入 **** 下的 ADDWT *，不执行专门判断。

相同列位置在不同函数中可以有不同含义，不能把 PIT 的参数解释直接套给 IF 或 P2003。

## 10. PITAB：保存、恢复或重置内部表

PITAB 不是“PIT 加 AB 参数”，也不是调用 PCR 逐条计算。

| 参数 1 | 作用 | 例子/说明 |
| --- | --- | --- |
| S | 将原表保存到辅助表 | PITAB S AIT：IT → AIT |
| L | 从辅助表装载回原表 | PITAB L AIT：AIT → IT，覆盖式装载 |
| D | 清空或重置指定表 | D IT 清空 IT；D DPS 有特殊初始化 |
| A | 按支持的表组合追加数据 | 不是任意两张表都可追加 |
| M | 按支持的表组合合并数据 | 具体方式看对应表的实现 |

实际列位置是“参数 1 = 操作码，参数 2 = 表标识”。表标识必须是函数支持的内部表，不是任意 SE11 数据库表。可参考 [SAP：PITAB S AIT 的方案例子](https://help.sap.com/docs/SAP_Best_Practices/36083acc10454111bdbf5f408e29c2f3/b3561e51d83a495eac27a9c2f8052989.html?version=2305)。

### 10.1 PITAB D DPS 为什么不能只翻译成“清空”

当前实现先清空 DPS，再遍历 PSP 复制记录，并将复制记录中的 ZMODN、TAGTY、ACTIV 字段初始化。

因此它是“根据 PSP 重置 DPS”，执行后 DPS 不一定是零条记录。

### 10.2 与其他复制、清除操作对照

| 写法 | 层次 | 操作对象 |
| --- | --- | --- |
| COPY XCOM | PE01 | 包含子 schema 的处理步骤 |
| PITAB S AIT | PE01 | 保存整张 IT 到 AIT |
| PITAB D DPS | PE01 | 重置 DPS |
| FILLF RNA | PE02 | 恢复当前记录的数值 |
| ADDWT 1000 | PE02 | 以指定工资项号输出当前记录 |
| ZERO= RNA | PE02 | 当前三个数值字段清零 |

## 11. IF：条件来自哪里

### 11.1 用 PCR 返回条件

~~~text
IF      ZCHK
  ……条件为真时执行……
ELSE
  ……条件为假时执行……
ENDIF
~~~

ZCHK 是教学用规则名。它需要通过 SCOND=T IF 或 SCOND=F IF 设置条件；只写 ADDWT * 不等于向 IF 返回真。

例如，判断 PCR 先执行 OUTWPPAYSB，在 BB 分支返回真，其他分支返回假。

### 11.2 使用内置条件

ZA01 有以下调用：

| 函数 | 参数 1 | 参数 2 | 参数 3 | 参数 4 |
| --- | --- | --- | --- | --- |
| IF | — | PDC | — | — |
| IMPRT | — | B2 | — | — |
| ENDIF | — | — | — | — |

PDC 是内置条件。当前实现根据相关时间管理状态判断，**不是检查 B2 是否已经存在可用结果**。

ZA01 另有 IF X064。本次读取的 PCR X064 只有 SCOND=T IF，因此当前条件直接为真，不能只根据名称或描述猜测它仍有其他判断。

### 11.3 三类操作的分工

| 名称 | 控制层次 |
| --- | --- |
| IF | 执行哪一段 schema |
| CMPER、OUTWP、VWTCL | PCR 内部走哪条判断分支 |
| SCOND | 将 PCR 判断结果交给调用它的 IF |

考勤 IF 与薪资 IF 的内置条件参数位置可能不同，不要跨领域照抄。

## 12. NEXTR：续行不是新建条件分支

BAESL_100 当前 ZPP2 的片段：

~~~text
判断路径：PPPAR A 返回 A
  初始行：
    RTE=TKGX**
    RTE-TAGX**
    RTE*8
    RTE+TSSOLL
    RTE*KGENAU
    NEXTR A

  同一判断路径，续行序号 A：
    RTE/TSDIVP
    ADDWT *
~~~

| A 出现的位置 | 含义 |
| --- | --- |
| PPPAR A 下的判断分支 A | 判断结果 |
| NEXTR A 指向的续行序号 A | 同一分支接着执行的行 |

当前配置中，后续行的判断键仍为 A，SEQNO 为 A。不能在 PPPAR 下额外建一个并列的“1”或“A”分支，就当作 NEXTR 的目标。

上例说明执行顺序；其中技术时间参数、固定 8 和因子精度是否适合某个人员，需要按具体计薪口径核对。

## 13. 阅读或排查的顺序

1. PE01 找调用行：函数、PCR、四个参数分别是什么，该行是否停用。
2. 看调用前的数据：IT/RT/ZL/WPBP 有什么，工资项是否分段。
3. PE02 确认入口：规则分组、工资项入口、GEN/NOAB 的影响。
4. 解释判断值：OUTWP 查哪个字段，CMPER 比哪个期间，VWTCL 查哪个处理类。
5. 跟踪 R/N/A：赋值、运算、清零后分别是多少。
6. 找 ADDWT：输出到哪里、工资项号是什么、保留什么 split、输出几次。
7. 看后续是否又估值、合并、过滤或生成相同工资项。
8. 对照结果同时记录人员、所属期、所在期、结果序号。

PE01 停用列中的标记和日志列中的标记含义不同，不能只看到星号就认为该行不执行。
