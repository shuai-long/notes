# 考勤常用 schema：按功能理解 PE01 与 PE02

> 整理日期：2026-10-12。通用概念参考 SAP 官方文档；项目例子已只读核对 BAESL_100 的 ZT28、相关 PCR 和标准实现。教学片段用于理解，不是完整上线规则。
>
> 配套笔记：[薪酬常用 schema](薪酬常用schema.md)。CMPER、ZERO=、OUTWPPAYSB、ADDWT、PITAB 的薪资用法在该笔记中展开。

## 1. 考勤 schema 主要在做什么

时间评估通常按人员、按日期读取计划和实际数据，再执行判断、分类、计算，形成时间余额和时间工资项。

它经常计算的是“小时数、天数、时间类型余额、工资项数量”，并不直接等于最终加班费或病假扣款金额。

| 层次 | 入口 | 作用 | 例子 |
| --- | --- | --- | --- |
| Schema（计算方案） | PE01 | 安排按日处理流程、调用子方案和 PCR | ZT28、TM00 |
| Function（函数） | PE01；PE04 查说明 | 读取数据、处理表、调用 PCR、控制流程 | P2001、PTIP、RTIP、ACTIO、IF |
| PCR（人员计算规则） | PE02 | 定义判断、计算、保存结果的步骤 | ZF00、ZF01 |
| Operation（操作） | PE02；PE04 查说明 | 对当前数据取值、判断、运算、输出 | HRS、VARST、ADDDB、COLOP |

**PE01 看流程和输入表，PE02 看当前数据怎么处理。**

标准方案中，TM00 常用于有打卡时刻的时间评估，TM01 对应只记录偏差的场景，TM04 支持有或无时刻的处理场景。项目复制、修改后应看实际内容，不能只凭方案名称判断。参见 [SAP：时间评估处理方式](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/c6c3ffd90792427a9fee1a19df5b0925/8334e153a217424de10000000a174cb4.html?locale=en-US&version=LATEST)。

## 2. 按目的快速查找

| 想做什么 | PE01 常用函数 | PE02 常用操作 | 关注点 |
| --- | --- | --- | --- |
| 读取缺勤、出勤、打卡 | P2001、P2002、P2011 | 读取后的规则再处理 | 生效日期、时间记录来源 |
| 读取或生成计划时间 | P2000、相关计划处理函数 | HRS=S、VARST | 当天计划工时、班次 |
| 遍历时间对 | PTIP、RTIP | OUTTP、COLOP | 是否重建 TIP |
| 处理日余额 | PDB | HRS=Dxxxx、ADDDB | TES 中的时间类型 |
| 处理累计余额 | PMB | HRS=Mxxxx、ADDMB | SALDO 的累计口径 |
| 比较数值 | 调用 PCR | HRS?… | 当前 HRS 与什么值比较 |
| 判断休息日、节假日 | IF 调用判断 PCR | VARSTFREE、VARSTHOLCL、VARSTDAYTY | 不同属性不能混用 |
| 加减乘除、换算 | ACTIO、PTIP 等调用 PCR | HRS、ROUND | 数量单位、除数 |
| 保留/输出时间对 | PTIP 等提供上下文 | COLOP | 不是写时间余额 |
| 写日余额、累计余额 | 调用相应 PCR | ADDDB、ADDMB | 累加还是覆盖 |
| 生成时间工资项 | GWT | ADDZL | 数量不等于现金金额 |
| 条件和子流程 | IF、ELSE、ENDIF、COPY、ACTIO | SCOND、PCY、GCY、NEXTR | 控制层次不同 |
| 日结、结果累计 | CUMBT | 前面的规则准备数据 | TES、DZL 如何进入结果 |
| 查看日志 | PRINT、BLOCK | PRINT | 输入、输出和判断路径 |

## 3. 内部表、日结果和累计结果

### 3.1 常见表与工作值

| 名称 | 含义 | 常见用法 |
| --- | --- | --- |
| TIP | 当前日的时间对输入表 | 已分类的出勤、缺勤、计划等时间段 |
| TOP | 时间对处理时的输出表 | COLOP 输出；PTIP 可据此形成后续 TIP |
| TES | 当前日时间余额工作表 | ADDDB 写入，HRS=Dxxxx 读取 |
| ZES | 按日保存的时间类型结果 | 查看某天累计了多少小时或天数 |
| SALDO | 时间评估期间的累计余额，通常称月余额 | ADDMB、PMB 等使用；不能直接当作全年合计 |
| DZL | 当前日时间工资项工作表 | GWT 或 ADDZL 产生 |
| ZL | 汇总保存、供薪资衔接的时间工资项 | 经后续薪资估值形成金额 |
| ZML | 加班相关的中间工作表 | POVT 等处理 |
| ERT | 时间评估错误/消息工作表 | PERT 处理，COLER 收集相应记录 |
| HRS | 当前计算使用的数值工作字段 | 暂存、比较、运算；不是一张表 |

TES、TIP 等是评估过程中的工作表。不能看到表名就假定能在 SE16 直接查到同名透明表。B2 结果中常见 ZES、SALDO、ZL，可参见 [SAP：时间评估结果](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/c6c3ffd90792427a9fee1a19df5b0925/e035e153a217424de10000000a174cb4.html?locale=en-US&state=PRODUCTION&version=2025.001)。

### 3.2 典型数据流

~~~mermaid
flowchart TD
  A["个人工作计划、缺勤、出勤、打卡等"] --> B["形成和分类 TIP 时间对"]
  B --> C["PTIP / RTIP / ACTIO 与 PCR"]
  C --> D["ADDDB：TES 日余额"]
  C --> E["GWT / ADDZL：DZL 时间工资项"]
  D --> F["CUMBT：按配置保存和累计"]
  E --> F
  F --> G["ZES：每日结果"]
  F --> H["SALDO：累计余额"]
  F --> I["ZL：时间工资项"]
  I --> J["薪资导入、估值和后续处理"]
~~~

这是常见衔接关系，具体生成点、累计方式和执行先后仍以项目 schema 为准。特别是“时间类型有值”不代表“一定生成同号工资项”。

## 4. PE02 操作：按功能分类

### 4.1 取值与赋值：HRS

HRS 可以理解成时间规则里的数值工作字段。先把需要的值放入 HRS，再比较、计算，最后用 ADDDB、ADDMB、ADDZL 等保存。

| 写法 | 含义 | 注意 |
| --- | --- | --- |
| HRS=0 | 当前 HRS 设为 0 | 不会单独清掉 TES 或 SALDO |
| HRS=8 | 当前 HRS 设为 8 | 单位取决于后续业务计算 |
| HRS=S | 取当天计划工作小时数 | 不等于固定 8 小时 |
| HRS=D9005 | 取 TES 中时间类型 9005 的当日余额 | 9005 是教学示例编号 |
| HRS=M9005 | 取 SALDO 中该时间类型的累计余额 | 需核对时间类型的累计设置和当前评估期间 |
| HRS?CGLMAX | 与常数 GLMAX 对应的值比较 | C 后是常数来源，不是时间类型 |

HRS 名称虽然与小时有关，但项目规则可能把它换算为天数、次数后保存。必须沿着运算过程判断单位。参见 [SAP：HRS、VARST 与 ADDDB](https://help.sap.com/docs/PRODUCT_ID/c6c3ffd90792427a9fee1a19df5b0925/e634e153a217424de10000000a174cb4.html)。

### 4.2 数值比较、加减乘除

| 写法 | 含义 |
| --- | --- |
| HRS?8 | 当前 HRS 与 8 比较，按 <、=、> 分支 |
| HRS+1 | 当前 HRS 加 1 |
| HRS-1 | 当前 HRS 减 1 |
| HRS*2 | 当前 HRS 乘 2 |
| HRS/8 | 当前 HRS 除以固定 8 |
| HRS/S | 当前 HRS 除以当天计划小时数 |
| ROUNDH>30 | 对当前 HRS 按 30 分钟间隔向上舍入 |

ROUNDH>30 的 H 指向当前小时数工作字段，30 是分钟间隔，不是“保留 30 位”或“30 小时”。本次已核对标准 ROUND 实现；上述解释用于普通非负时长，例如 1.1 小时向上到 1.5 小时。

HRS/S 常用于“小时 → 计划工作日比例”，但必须确认当天计划小时数不为 0。不能因为某个工作日是 8 小时，就把所有 HRS/S 统一改为 HRS/8。

### 4.3 判断日期、工作计划和时间对属性

| 操作 | 查询什么 | 易错点 |
| --- | --- | --- |
| VARSTFREE | 当天是否为无计划工作时间的空闲日 | 不能简单等同于星期六、星期日 |
| VARSTHOLCL | 当天节假日类别 | 节假日类别和日期的星期几不同 |
| VARSTDAYTY | 当天日类型 | 日类型与节假日类别不同 |
| VARSTDAYPG | 当天日工作计划 | 通常返回日工作计划代码 |
| VARSTDPRCL | 日工作计划类别 | 类别与班次名称不同 |
| VARSTFIRST | 是否为当前 TIP 处理中的第一条记录 | 不是本月第一天 |
| VARSTLAST | 是否为当前 TIP 处理中的最后一条记录 | 不是本月最后一天 |
| VARSTP2001 | 缺勤数据装载相关状态 | 不是直接返回病假天数 |
| OUTTPVTYPE | 当前时间对的处理类型 | 例如 S、M；不是人员编号 |
| VARPRTYP | 当前记录的相关类型键，可用于出勤/缺勤类型分流 | 必须看调用时传入的记录 |

VARST 后面的参数决定查什么，不能把所有 VARST 都理解成“判断是否上班”。

例如 VARSTFREE 返回 Y/N 后，再在对应分支判断 VARSTHOLCL，表达的是两个连续条件。SAP 有 [VARST 与通用分支的规则例子](https://help.sap.com/docs/HR_RENEWAL_SPV/220fd126c5364a7eb6237f4722473e93/e934e153a217424de10000000a174cb4.html)。

### 4.4 复制、输出和累计

| 操作 | 目标 | 做什么 |
| --- | --- | --- |
| COLOP* | TOP | 保留/输出当前时间对 |
| ADDDB9005 | TES | 将当前 HRS 累加到当日时间类型 9005 |
| ADDDB9005Z | TES | 用当前 HRS 替换当日时间类型 9005 的值 |
| ADDDB9005- | TES | 按当前 HRS 的相反数累计到该时间类型 |
| ADDDB9005T | TES | 使用当天计划工时加入该时间类型 |
| ADDMB9005 | SALDO | 将当前值加入对应累计余额 |
| ADDZL9005 | DZL | 生成指定时间工资项记录；数量等依参数和上下文处理 |

ADDDB 的普通形式、Z、-、T 是不同写法；不能只看前五个字符。ADDDB9005Z 是覆盖，不是普通累加。

**时间类型 9005 和工资项 9005 属于不同编号体系。** ADDDB9005 与 ADDZL9005 即使数字相同，目标和用途也不同；此处编号仅用于教学。

各处理函数与工作表的对应关系，可参见 [SAP：时间评估内部表的处理](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/c6c3ffd90792427a9fee1a19df5b0925/ec34e153a217424de10000000a174cb4.html)。

### 4.5 清零和重写

~~~text
HRS=0
~~~

只清当前数值工作字段。

~~~text
HRS=0
ADDDB9005Z
~~~

将 TES 中时间类型 9005 的当前日值改为 0。

~~~text
HRS=0
ADDDB9005
~~~

向现有日余额加 0；已有余额通常保持原值，不是清空。

上述操作都不等于“删除全年 9005 的历史结果”。若当天后续规则再次写入 9005，日终结果还会继续改变。

### 4.6 调用、跳转和条件返回

| 操作 | 作用 |
| --- | --- |
| PCY | 调用子 PCR，处理后返回 |
| GCY | 转到另一 PCR 继续处理，与 PCY 的返回行为不同 |
| NEXTR A | 同一规则路径接着执行序号 A 的后续行 |
| SCOND=T IF | 向调用方 IF 返回真 |
| SCOND=F IF | 向调用方 IF 返回假 |
| PRINT | 输出相关评估信息到日志 |

NEXTR 的字母或数字是续行序号，不是新增的判断结果。详见配套薪酬笔记中的 ZPP2 例子。

## 5. PE01 函数：按功能分类

### 5.1 初始化与按日处理框架

| 函数 | 主要作用 |
| --- | --- |
| BINI | 初始化处理块的开始 |
| EINI | 初始化处理块的结束 |
| BDAY | 开始某一天的处理 |
| EDAY | 结束该日处理 |
| BEND | 全部逐日处理完成后，最终处理块的开始 |
| EXPRT | 输出/保存评估结果 |
| EEND | 最终处理块的结束 |
| CHECK | 检查是否继续处理相应日期/场景，条件由参数指定 |

读 schema 时先找三个块：BINI—EINI 初始化，BDAY—EDAY 逐日处理，BEND—EEND 最终处理。前后两块通常每人每次评估执行一次，中间块按日执行；BINI/BEND 的 B 不能理解成“缓冲表”。参见 [SAP：Schema 处理阶段](https://help.sap.com/docs/ERP_HCM/220fd126c5364a7eb6237f4722473e93/dd34e153a217424de10000000a174cb4.html)。

### 5.2 读取计划与时间记录

| 函数 | 主要作用 | 常见来源 |
| --- | --- | --- |
| P2000 | 根据个人工作计划生成计划时间对 | 不是读取所谓 IT2000 的简单通用函数 |
| P2001 | 处理缺勤记录 | IT2001 |
| P2002 | 处理出勤记录 | IT2002 |
| A2003 | 将替代记录用于相应时间处理 | IT2003 |
| P2005 | 处理加班记录 | IT2005 |
| P2011 | 处理时间事件/打卡 | 时间事件数据 |
| P2012 | 处理时间转移规格 | IT2012 |
| P2013 | 处理配额更正规格 | IT2013 |

函数名称相似不代表执行方式相同。薪资侧的 P2003 与考勤侧的 A2003，也应分别查文档。

### 5.3 遍历表并调用 PCR

| 函数 | 主要处理对象 | 用途 |
| --- | --- | --- |
| PTIP | TIP | 调用 PCR 处理时间对，输出可以改变后续 TIP |
| RTIP | TIP | 读取时间对并调用 PCR，通常用于取值、累计，保留原 TIP |
| ACTIO | 不要求逐条遍历 TIP | 直接执行一条 PCR，例如日余额换算 |
| PDB | TES | 对日余额逐条调用 PCR |
| PMB | SALDO | 对累计余额调用 PCR |
| PZL | DZL | 处理日时间工资项 |
| POVT | ZML | 处理加班中间结果 |
| PERT | ERT | 处理时间评估错误/消息记录 |

PTIPA、RTIPA 是针对存在缺勤情形的相应处理变体，不能无条件当成 PTIP、RTIP 的别名；具体处理条件、参数和分组方式应按 PE04 查看。

### 5.4 时间分类、工资项生成与累计

| 函数 | 主要作用 |
| --- | --- |
| TIMTP | 对时间对进行分类、分配相应时间类型/处理属性 |
| PBRKS | 处理休息时间及其与时间对的关系 |
| DAYMO | 设置时间工资项选择使用的日分组 |
| GWT | 根据时间工资项选择规则生成工资项，常涉及 T510S |
| LIMIT | 按配置处理时间余额等的限额 |
| CUMBT | 将当日余额和工资项按配置保存、累计 |
| QUOTA | 按配额生成规则处理缺勤配额相关结果 |

CUMBT 对 TES 的处理受时间类型累计设置影响，不能理解为“所有 TES 一律原样加到所有累计表”。参见 [SAP：时间余额的累计](https://help.sap.com/docs/PRODUCT_ID/a2ea466742c4424a9d4063faedf19d93/0635e153a217424de10000000a174cb4.html)。

### 5.5 流程控制与日志

| 函数 | 作用 |
| --- | --- |
| COPY | 包含子 schema |
| IF / ELSE / ENDIF | 按条件选择执行哪段流程 |
| BLOCK | 组织处理块和日志层次 |
| PRINT | 输出指定内部表或处理信息 |
| MOD | 调用相应规则设置处理所需分组 |

COPY 后面是子 schema；ACTIO、PTIP、RTIP 后面通常是 PCR。两者都表现为“调用一个名字”，但调用对象不同。

## 6. PTIP、RTIP 与 COLOP 的关系

### 6.1 PTIP：处理输入时间对并形成输出

可以按下面的顺序阅读：

~~~text
TIP 当前记录
    ↓
PCR 判断、修改
    ↓
COLOP*
    ↓
TOP
    ↓
PTIP 完成后的后续 TIP
~~~

在这种重建输出的上下文中，某条路径没有输出时间对，可能导致该时间对不再传给后续处理。因此，修改 PTIP 调用的规则时，既要看 ADDDB，也要看 COLOP。

### 6.2 RTIP：读取时间对，不要直接套用 PTIP 的删除语义

RTIP 常用于读取 TIP 进行累计；它与 PTIP 对输入时间对的保留方式不同。不能看到 RTIP 调用的规则某个分支没有 COLOP，就断言该时间对被删除。

### 6.3 COLOP 与 ADDDB 可以同时出现

~~~text
ADDDB9005
COLOP*
~~~

前一条把当前 HRS 加入日余额，后一条输出当前时间对。两条操作负责不同结果，不是重复计算同一张表。

同样，只有 COLOP 不代表已经增加日余额；只有 ADDDB 也不代表已经产生薪资工资项。

GWT 行中的 S 在参数 2、DZL 在参数 3。不能只记成“GWT S DZL”，再把 S 填进参数 1。

### 7.2 ZF00：按当前时间对类型累计

当前 ZF00 中有以下路径，下面省略其他分支：

~~~text
VARSTDPRCL
  非 0 的相应分支
    OUTTPVTYPE
      S
        VARPRTYP
          9210
            ADDDB9350
            COLOP*
~~~

读法：

1. 先按日工作计划类别分流。
2. 再判断当前时间对处理类型。
3. 对相关类型键为 9210 的记录，把当前数值累计到日时间类型 9350。
4. COLOP* 处理当前时间对的输出。

这里的 9210、9350 是项目配置中的不同类型编号，不能仅根据编号认定其中文业务含义。该 PCR 当前由 RTIP 调用，因此分析时间对是否保留时应使用 RTIP 的处理语义。

### 7.3 ZF01：读取日余额、舍入、覆盖，再换算

当前 ZF01 的一个处理段为：

~~~text
HRS=D9350
ROUNDH>30
ADDDB9350Z
HRS/S
ADDDB9300
NEXTR A
~~~

| 顺序 | 操作 | 作用 |
| --- | --- | --- |
| 1 | HRS=D9350 | 从 TES 读取 9350 的当日值 |
| 2 | ROUNDH>30 | 对当前小时数按半小时向上舍入 |
| 3 | ADDDB9350Z | 用舍入后的值覆盖当日 9350 |
| 4 | HRS/S | 除以当天计划小时数，形成相应比例 |
| 5 | ADDDB9300 | 将换算后的值加入当日 9300 |
| 6 | NEXTR A | 继续同一路径的下一续行 |

按“当前值为 2.2 小时、当天计划 8 小时”的教学假设：

- 舍入后为 2.5 小时。
- 9350 被改写为 2.5。
- 换算值为 2.5 ÷ 8 = 0.3125。
- 9300 增加 0.3125；实际保存精度还取决于结果字段和后续规则。

这段代码并非对所有日期无条件执行。当前 ZF01 前面还有 VARSTFREE、VARSTHOLCL 等条件，并通过相应规则分支进入此段。

## 8. IF：考勤内置条件与 PCR 条件

考勤 PE01 也使用 IF / ELSE / ENDIF，但它与薪资 IF 的参数安排不能混用。

ZT28 当前例子：

| 函数 | 参数 1 | 参数 2 | 参数 3 | 参数 4 | 含义 |
| --- | --- | --- | --- | --- | --- |
| IF | — | — | POS | — | 查询 POS 内置时间评估场景条件 |
| IF | — | NOT | SIMF | — | 对 SIMF 条件取反 |
| IF | ZG06 | — | — | — | 由 PCR ZG06 返回条件 |
| IF | — | — | EOM | — | 查询评估月末条件 |

NOT 在参数 2，内置条件在参数 3。不要把薪资 IF 的 PDC 参数列直接套到考勤。

如果用 PCR 返回条件，该 PCR 通过 SCOND=T IF 或 SCOND=F IF 设置真假。VARST、HRS? 等负责 PCR 内部判断，IF 负责外层 schema 流程。

VARSTLAST 判断的是时间对处理中的最后一条记录；月末条件 EOM 属于另一件事。

## 9. 考勤与薪酬操作对照

| 功能 | 考勤常见写法 | 薪酬常见写法 | 不能忽略的区别 |
| --- | --- | --- | --- |
| 数值工作字段 | HRS | RTE、NUM、AMT | 小时/天数与费率/数量/金额的语义不同 |
| 比较 | HRS?、VARST、OUTTP | AMT?、NUM?、RTE?、CMPER、OUTWP | 取值来源和上下文不同 |
| 当前数值清零 | HRS=0 | ZERO= RNA | 都不等于清空历史结果 |
| 传递当前记录 | COLOP | ADDWT | 时间对与工资项不是同一种记录 |
| 日余额累计 | ADDDB | 不是简单一一对应 | 时间类型与工资项不能混为一谈 |
| 生成时间工资项 | ADDZL、GWT | ZLIT 后继续薪资处理 | 有数量不等于已有金额 |
| 包含子方案 | COPY | COPY | 都是 schema 层次 |
| 调规则/续行 | PCY、GCY、NEXTR | PCY、GCY、NEXTR | 仍要核对各领域的参数 |
| 整张工作表保存/恢复 | 看具体时间函数 | PITAB | PITAB 是薪资笔记重点，不应当成通用考勤表工具 |

用户常见的 CMPER 2606，是薪资所属期间的比较写法；不应拿它替代时间评估中对“当前正在处理的那一天”的日期判断。

## 10. 常见误读与排查顺序

### 10.1 常见误读

| 误读 | 应如何理解 |
| --- | --- |
| HRS=0 就清掉了当天病假 | 只清工作字段，必须看后续写入目标 |
| ADDDB9005 与 ADDDB9005Z 一样 | 前者累计，后者覆盖 |
| ADDDB9350 就生成了工资项 9350 | 它写的是日时间类型，不是薪资 RT |
| ADDZL 已算出加班费金额 | 通常先形成时间工资项，金额还可能待薪资估值 |
| FREE 就是周末，HOLCL 就是星期几 | 计划空闲日、节假日类别、星期几是不同维度 |
| VARSTFIRST/LAST 是月初/月末 | 它们判断 TIP 处理中的首末记录 |
| 每次 ADDDB 后 HRS 自动归零 | 不能这样假设；接下来的指令仍使用当前工作值 |
| 月余额可以直接当全年累计 | 要核对时间类型累计、结转和期间边界 |
| 没有 COLOP 一定删了 TIP | 必须先分清调用方是 PTIP 还是 RTIP 等 |
| 同一 PCR 放在任意位置都一样 | 上游取值、分组、当前日及下游累计都影响结果 |

### 10.2 阅读日志的顺序

1. 先确定人员与当前处理日期，尤其是追溯重算时。
2. 确定调用函数：PTIP、RTIP、ACTIO、PDB、PZL 分别拿什么数据。
3. 记录输入 TIP 的类型、时长和计划；不要只看最终汇总。
4. 逐步记录 HRS 的值和单位，确认每次取值、舍入、除法。
5. 找到输出目标：COLOP → 时间对，ADDDB → 日余额，ADDZL → 时间工资项。
6. 检查同一时间类型是否在同一天被重复累计、后续覆盖或重新生成。
7. 再看 CUMBT 后的 ZES、SALDO、ZL，核对是否为正确人员和日期。
8. 与薪资核对时，继续追踪导入后的工资项、所属期、回算期间和估值规则。

“年度前 5 天”等规则还需要确认累计起点、是否包含当前日、跨年重置和重算覆盖方式；仅看到一个 ADDDB 或 SALDO 数值不足以判断完整口径。
